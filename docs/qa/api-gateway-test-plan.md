# Test plan: api-gateway (phase 1)

- Feature: `api-gateway`. Spec `docs/specs/api-gateway.md`, status Changes requested, last updated 2026-10-12, 50 ACs.
- Contract: `docs/api/api-gateway.openapi.yaml`, version 0.2.0 (edge conventions, OpenAPI 3.1.0).
- Run instructions: `api-gateway/README.md`.
- Code under test: commit `aa2234c` + the uncommitted working tree. That is backend-swe's T1–T12 and the fix round
  T13–T19.
- Author: qa, 2026-10-12. This revision covers the re-verification after the fix round. Results are in
  `docs/qa/api-gateway-report.md`.

## 1. Scope

In scope:

- All 50 acceptance criteria of US-1 to US-8. These are the original 41, with AC-1.3 now stating the JSON content type
  and AC-4.3 titled "a timed-out request", plus 9 new ones: AC-1.7, AC-2.9, AC-2.10, AC-4.6, AC-4.7, AC-4.8, AC-7.6,
  AC-7.7 and AC-7.8.
- Adversarial checks of the edge decisions D2–D7 as amended on 2026-10-12: forged tokens, ambiguous credentials,
  public-operation bypass, header abuse, leakage, CORS, unknown paths, downstream failure modes before and after the
  response headers, and state isolation under concurrency.
- Contract spot checks.
- Re-verification of every first-round bug (BUG-api-gateway-1 to 13).

Out of scope:

- The spec's own out-of-scope items.
- The follow-ups FU-1 to FU-5. Their reproduction tests stay disabled under D10, and their behaviour is only observed.
- Known auth-service defects 1–6, except where they affect AC-2.8.

are out of scope (spec, "Users and roles").

  copied into QA documents. The user is `ana@example.com` / `Secret123!` / "Ana Lima" on a fresh H2 database. Tokens

## 6. Risks and items not covered

- **Manual-only ACs.** AC-1.6, AC-2.8 and AC-8.6 are manual only (D8). They depend on a fresh in-memory auth-service.
- **Committed responses (FU-4, BUG-14).** These are responses over 8 KB, or streaming media types, that fail mid-body.
  Their handling is deferred and not covered by AC tests. Currently a chunked 200 can be completed with an appended
  Problem.
- **Framework coupling.** The T15 classification depends on Spring Cloud Gateway running response header filters on the
  request thread (`RequestContextHolder`). Re-run AC-4.6 and AC-4.7 on every Spring Cloud upgrade.
- **Connect timeout.** A connect timeout to an unreachable (black-holed) host is not automated (A11). Only connection
  refused is covered.
- **Container-level rejections.** Requests Tomcat rejects before any filter runs (encoded slash, `%00`, `TRACE`,
  `CONNECT`) bypass the request ID and the access log. They are out of scope per D6.
- **Load.** Concurrency was tested only up to 200 requests in the exploratory probe and 60 in the QA test. There was no
  load test.
- **Shared stubs.** `GatewayIntegrationTest` shares static stubs across test classes. That is safe with Gradle's default
  sequential execution, but parallel JUnit execution in one JVM would break it.
